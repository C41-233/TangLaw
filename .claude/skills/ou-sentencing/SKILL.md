# 殴斗量刑一致性

本 skill 用于确保《唐律疏议》注解项目中与"殴、斗殴、故殴"相关的量刑内容，在五个来源之间保持一致。

## 五个来源的定位

| 来源 | 路径 | 定位 |
|------|------|------|
| 释义量刑表 | `src/释义/量刑表/` | 五行（后果×手段）基准表，按罪名分子目录：`殴打/`（殴打量刑表系列）、`殴打/斗殴/`（斗殴量刑表系列 + 斗杀量刑表）、`殴打/故殴/`（故殴量刑表系列 + 故杀量刑表）、`过失杀伤/`（过失杀伤人系列） |
| 斗殴罪刑表 | `src/附录/3-罪刑表/8-斗讼律/1-斗殴.xml` | 斗殴罪名下的罪刑对应总表（含总结、word 引用） |
| 故殴罪刑表 | `src/附录/3-罪刑表/8-斗讼律/2-故殴.xml` | 故殴罪名下的罪刑对应总表 |
| 量刑表 | `src/附录/4-量刑表/` | 按刑罚等级（死刑/流刑/徒刑/杖刑/笞刑）分类的罪刑对应表 |
| 尊卑相犯表 | `src/附录/5-尊卑相犯/` | 按尊卑主体（父母子女、夫妻、期亲、大功、小功、缌麻、部曲奴婢主人）分类的罪刑对应表（x-table） |

**"之一~之六"的范围**：本 skill 所称"之一~之六"（转置总表）包含**两套十二个文件**——`殴打/斗殴/斗殴量刑表之一~之六` 与 `殴打/故殴/故殴量刑表之一~之六`；同属该体系的还有 `殴打/斗殴/斗杀量刑表`、`殴打/故殴/故杀量刑表`（致死类汇总表）。凡涉及"之一~之六"的核对，均须同时覆盖斗殴与故殴两套，且致死行须与斗杀表、故杀表交叉核对。

**"殴打"的双重罪名属性**：`殴打/殴打量刑表` 系列（殴打类基准表，如殴打量刑表（妻殴夫）、（缌麻兄姊）、（缌麻尊属）、（小功兄姊））**同时被斗殴罪刑表（`1-斗殴.xml`）与故殴罪刑表（`2-故殴.xml`）引用**——即"殴打 = 斗殴 + 故殴"两个罪名维度共用同一基准表。因此：罪刑表的斗殴、故殴两处都须引用对应的殴打量刑表；`4-量刑表` 中殴打类条目仅以"殴打（主体）"呈现，**不单列"故殴（主体）"条目**（故殴维度由殴打表与故殴量刑表系列覆盖）。

## 为什么需要一致

量刑表是**权威详细表**（后果×手段的完整刑罚矩阵），其余四处是对它的投影/归类：
- `1-斗殴.xml`、`2-故殴.xml` 通过 `<word>` 引用转置总表（斗殴/故殴之一~之六）及斗杀、故杀表，行/列刑罚必须与量刑表一致
- `4-量刑表` 将量刑表各行的刑罚按等级归入对应刑罚文件，条目及其刑罚必须与量刑表一致
- `5-尊卑相犯` 将亲属尊卑相犯的刑罚按主体归入对应文件（父母子女、夫妻、期亲、大功、小功、缌麻、部曲奴婢主人），条目及其刑罚必须与量刑表一致

一处改动而不同步其他处，会导致网站各页刑罚互相矛盾。

## 主体命名规范（完整名 vs 代表名）

用户既定命名规则，适用于亲属主体称谓：

- **仅 `5-尊卑相犯` 层使用完整类推名**（完整列举）：如 `祖父母、曾祖父母、高祖父母`、`孙（女）、曾孙（女）、玄孙（女）`、`从父兄弟之子女`。
- **其余所有位置**（罪刑表 `1-斗殴.xml`/`2-故殴.xml`、正文、`4-量刑表`、转置表之一~之六、五行表专属表名）**使用代表名**：`祖父母`、`孙`、`从父兄弟之子`。

| 完整类推名（仅 5-尊卑相犯） | 代表名（其余） |
|---|---|
| 祖父母、曾祖父母、高祖父母 | 祖父母 |
| 孙（女）、曾孙（女）、玄孙（女） | 孙 |
| 从父兄弟之子女 | 从父兄弟之子 |

- **word value 必须与 `src/释义/` 下对应表文件名（不含扩展名）精确一致**（generator `CollectWords` 以文件名为 key）。改动完整名/代表名时，须**同步重命名**对应表文件，并同步罪刑表/正文的 `<word value>`；否则引用失效。
- `5-尊卑相犯` 的目录/文件名/表标题用完整类推名（如 `1-从父兄弟之子女.xml`），不受"其余用代表名"约束。

## 排序规则（适用所有"殴打"情况）

用户既定排序，适用于所有殴打情况（斗殴/故殴/殴打；不同来源/表可能缺少某些项，但大体排序都应遵守，缺项不补齐）：

1. **罪名标记**：斗殴 > 故殴 > 殴打（无标记）。
2. **大类**：凡人 > 夫妻媵妾 > 特定亲属 > 通用亲属。
3. **夫妻媵妾内部**：夫 > 妻 > 媵 > 妾。
4. **特定亲属**：指具体的亲属，先尊后卑。
5. **通用亲属**：指期亲、大功、小功、缌麻，先尊后卑。

## 聚合合并规则（尊长 / 卑幼）

- **尊长 = 尊属 + 兄姊**：若某级 **尊属** 与 **兄姊** 的**后果、量刑、十恶、法条都一致**，应合并为 `X尊长`；否则保留原 `X尊属` / `X兄姊`。（比第 8 条技术教训更严格：十恶与法条也须一致。）
- **卑幼 = 卑属 + 弟妹**：同理，若某级 **卑属** 与 **弟妹** 的**后果、量刑、十恶、法条都一致**，应合并为 `X卑幼`；否则保留原 `X卑属` / `X弟妹`。
- **妻媵妾 / 媵妾 聚合**：夫妻媵妾大类内，**妻、媵、妾**（或其中 **媵 与 妾**）若**后果、量刑、十恶、法条都一致**，可合并为 `X妻媵妾`（三者）或 `X媵妾`（二者）；否则保留原 `X妻` / `X媵` / `X妾`。
- **聚合前必须逐档验证子主体值全等**：读各子主体"殴打量刑表/五行表"逐后果×手段比较，**仅全等档可聚**；`妻 vs 媵妾`、`媵 vs 妾` 在**多数档不同**（妻/媵 通常轻于 妾/媵妾），常只"致死"等个别档全等（如 媵殴妻 vs 妾殴妻、妻殴夫 vs 媵妾殴夫）。勿仅凭词形或法条推断可并；曾误合 `媵妾犯妻` 把不同值的 媵/妾 并掉一侧。
- **`4-量刑表` 致死主体须完整**：以 `斗杀/故杀` 表 + 五行表为准逐主体核对 4-量刑表 勿缺（曾缺 `夫犯妻（致死）`）。

## 十恶标注（殴斗相关）

- **恶逆**：杀夫（妻/媵/妾 杀夫）→ 恶逆；可聚合 `妻媵妾犯夫（致死）＝恶逆`。（凡被杀者=夫，不论妻/媵/妾一律恶逆。）
- **不睦**：**妻殴夫**（非致死）→ 不睦；**媵妾殴夫**（非致死）→ 不标（媵妾非缌麻以上亲，不入不睦）；**夫殴妻（非致死）→ 不属不睦**；**夫杀妻（夫犯妻 致死）→ 不睦**（《325》疏议"杀妻，仍为不睦"，仅"以凡人论"之致死特申明）。
- **过失伤/杀**：不标（过失不入十恶）。
- **分档，勿一刀切**：同一"罪性质×主体"内标注统一；对"妻/媵妾"勿统一标或不标——非致死分 妻=不睦/媵妾=不标，致死统一 恶逆。

## 修改/补充时的一致性检查

涉及"殴、斗殴、故殴"的任何刑罚增删改，按以下流程核对：

1. **改动定位**：明确改的是哪一处（量刑表五行表 / 之一~之六 / 罪刑表 / 4-量刑表条目 / 5-尊卑相犯条目）。
2. **权威基准**：以 `src/释义/量刑表/` 中的五行表为刑罚基准（五刑按唐律规则：笞杖徒流死）。
3. **同步范围**：
   - 改了五行表的某行刑罚 → 检查对应的之一~之六（如有）、`1-斗殴.xml`/`2-故殴.xml` 对应行、`4-量刑表` 与 `5-尊卑相犯` 对应条目是否一致
   - 改了 `4-量刑表` 或 `5-尊卑相犯` 条目 → 反查五行表对应行刑罚
   - 改了罪刑表 → 反查量刑表
4. **行名/分组一致**：五行表按"之一~之六"分组合并后的行名（如 `致血从耳目出\n致内损吐血`、`致折肋\n致眇两目`），与罪刑表、之一~之六的列名/行名保持一致。
5. **方式列一致**：用手足、用器物、用汤火、用刃、用兵刃各列的刑罚与五行表一致；"用汤火伤人视同折伤"、斫射用手足留空等规则保持统一。
6. **主体一致**：凡人、祖父母/父母、夫殴妻、夫殴妾、妻殴妾、妻殴夫、媵殴夫、妾殴夫（以及妾殴媵、妾殴妻、媵殴妻、过失杀伤夫等）在各处的客体/主体表述与刑罚对应一致，尤其要与 `5-尊卑相犯` 各主体表（父母子女、夫妻、期亲、大功、小功、缌麻、部曲奴婢主人）一致。
7. **特殊规则**：
   - 殴祖父母、父母者斩（329 条），各来源相应位置均为斩
   - 殴夫（妻/媵/妾犯夫）致堕胎逻辑不通，相关表已删致堕胎行或标 ×
   - 夫殴妾"殴妾折伤以上减妻二等"，未致折伤无罪（无罪（未致折伤））
   - 致死行按斗杀表：凡人/夫殴妻/妻殴妾绞（手足器物）斩（刃）斩以故杀论（兵刃），殴夫皆斩

## 卑幼亲等谱系（327.1 减等递进）

`327.1 殴伤卑幼罪` 的折伤减等（"缌麻减凡人一等，小功、大功递减一等"）与致死规则，建立卑幼谱系：

| 主体 | 折伤减等 | 折伤换算 | 致死（斗殴）（未深究前统一绞） |
|------|---------|---------|------|
| 缌麻卑幼 | 减凡人一等 | = 凡人 - 1 | 绞 |
| 小功卑幼 | 减凡人二等 | = 缌麻卑幼 - 1 等 | 绞 |
| 大功卑幼 | 减凡人三等 | = 小功卑幼 - 1 等 | 绞 |
| 从父弟妹 | = 大功卑幼（折伤同） | 折伤同大功卑幼 | 见下（专条） |

- 新建某卑幼量刑表 = 相邻较疏卑幼表**每格减一等**（致死不变）。
- **致死当前统一取绞**（含 从父弟妹，用户明确"统一绞，从父弟妹专条后续再调"）。
- **从父弟妹专条**（327.1 第二款："即殴杀从父弟妹及从父兄弟之子孙者，流三千里；若以刃及故杀者，绞"）——**本会话已按此修改** `斗殴量刑表（从父弟妹）`：
  - 斗殴致死：用手足/器物/汤火 = **流三千里**（殴杀）；用刃 = 绞；用兵刃 = 绞（以故杀论）
  - 故殴致死 = 绞（故杀本就绞）
  - 注意：此专条使大功卑幼族系里"斗殴致死"分两档（从父弟妹流三千里、其余绞），故 4-量刑表里 从父弟妹 斗殴致死入**流三千里.xml**、故殴致死入**绞.xml**（与一般大功卑幼都入绞.xml不同）。

## 用刃致伤 vs 用刃致折伤

- **用刃致伤（未达折伤）** = 无罪（未致折伤）→ **不列入刑罚表**（因"非折伤不坐"）。
- **用刃致折伤** = 可罚，刑罚表写 **"（用刃）致折伤"**（用刃造成折伤，值 = 该主体用刃折伤基准值）。
- 转置表之三"用刃致伤"列中 卑幼 的 `无罪（未致折伤）`，一律改为 `（用刃折伤值）（致折伤）`，如 缌麻卑幼=徒一年半（致折伤）。
- 修正既有数据时，仅改"（用刃）致伤"→"（用刃）致折伤"，不动凡人/夫妻等本就正确的行。

## 用兵刃斗殴致死加（以故杀论）

- **所有"用兵刃斗殴致死"都加（以故杀论）**；用手足/器物/汤火/用刃 及 故殴（故杀）**不加**。
- 作用范围：`斗杀量刑表`（用兵刃列）及主体量刑表（全表）五行的致死行用兵刃格。
- 故杀量刑表不适用（故杀不加标记）。

## 4-量刑表 斗殴/故殴/殴打 合并格式

4-量刑表内 `斗殴/故殴/殴打` 三类**全部合并为 `殴打`**（罪行列统一为 殴打）：

- **（斗殴）/（故殴）标记放情形列最前**：`殴打\t（斗殴）主体（后果）`。
- **同刑罚合并**：同一（情形+十恶+法条）下 斗殴 与 故殴 并存 → 合并为一行、**不加标记**（如 卑幼致死 斗殴/故殴皆绞 → `主体（致死）` 无标记）。
- **组内排序**：`（斗殴）→（故殴）→无标记`，组内按法条升序。
- **情形列格式**：主体（客体）**去括号**、后果**套括号**；无客体补 **凡人**（如 `为奴婢（未遂）` → `凡人（为奴婢）（未遂）`）。卖人类别后果含 既遂/未遂/已售/未售 时，状态**单独括号**：`客体（为奴婢）（未遂）`。
- 参见 `1-斩.xml`、`2-绞.xml`、`1-流三千里.xml` 中已改好的示例（主体裸文本 +（后果））。

## 5-尊卑相犯 斗殴/故殴/殴打 合并（与 4-量刑表 同规则）

`5-尊卑相犯` 各主表（卑幼：缌麻/小功/大功/从父弟妹；夫妻：夫/妻/媵/媵妾）里的 `斗殴/故殴` 行，也按上面规则**合并为 `殴打`**（标记最前、同刑合并、斗殴→故殴→无标记排序）；闻丧/居丧/告/诬告/诈称/过失 等**非殴打行保留**。

**⚠️ 分表合并（易错）**：一个文件里可能有**多张 `<x-table>`**、每张代表**不同关系**（如 `2-媵妾/-.xml` 含 `夫对媵妾的犯罪` 与 `妻对媵妾的犯罪` 两张大表，刑罚不同：夫用汤火=杖七十、妻=杖九十）。**必须按 `<x-table>` 分块、每块各自合并**，否则会把两张表合并成一块、丢失"夫 vs 妻"区分。单表文件（卑幼、2-妻.xml、1-媵.xml）直接合并即可。
- 合并前用 `git diff` 看该文件原始结构（是否多表、各表主体），勿盲目全文件合并。
- 判"同刑"用 key=`情形|法定刑|十恶|法条`（**法定刑必须入 key**，否则 杖七十/杖九十 会被误判同刑）。

## 同一主体多行合并（同一主体+同法条+同刑罚级）

同一主体（同 标记+主体+法条）在某刑罚级文件里有**多行不同后果**时，应合并为一行：
- **按最低后果写**；最低后果为 **未伤** 时**可省略**（仅写 `殴打 主体`）。
- 组内**无未伤** 时，最低后果需**逐类询问用户**确认（勿自行断定）。
- 操作前先用脚本列出所有"同一主体+同法条+多行"的组，避免遗漏。

## 禁止越界（非殴打罪行）

- 只做任务范围内的 **殴打/斗殴/故殴** 相关增删改。
- **不擅自**创建/修改 闻丧、居丧、告、诬告 等**非殴打罪行**内容（除非用户显式要求）。
- `5-尊卑相犯` 各卑幼文件里的 闻丧/居丧/告/诬告 是**用户既有数据**，仅在其基础上补斗殴/故殴行，勿重写/勿代入未经验证的值；若需为某子类新建尊卑相犯文件，只应含**殴打破害相关行**。

## 实操技术教训（防止再犯）

1. **PowerShell 单元素数组展平**：`@(@('a','b'))` 会**展平**为 `@('a','b')`，导致循环取值变成逐字符；多元素 `@(@('a','x'),@('b','y'))` 不展平。单元素需用 `,@('a','b')` 或直接构造字符串，勿用单元素内层数组。
2. **减等映射须覆盖全部值**：如 徒一年半→徒一年，漏了会导致该档未减。
3. **字面反引号-t**：单引号 `'殴打`t...'` 是字面反引号+t，不会变成 Tab；构造含 Tab 的行要用双引号 `` "殴打`t..." ``。
4. **单行匹配别当数组**：`(... | Where-Object {...})` 单结果会成标量，`$r[0]` 取到首字符；需强制数组 `@(...)[0]`。
5. **逐格脚本校验**：改完用脚本对照基准表逐格验证（如 大功卑幼=小功卑幼-1），勿仅目检。
6. **多表合并勿跨表**：一个 XML 文件含多张 `<x-table>`（不同关系）时，合并/改写须**按表分块**逐块处理；误用"全文件首次~最后出现"的 span 会把多张表并成一块丢主体区分（如 媵妾/-.xml 的 夫对媵妾 + 妻对媵妾）。合并前先 `git diff`/读文件确认结构。分组 key 务必含**法定刑**（避免不同刑被误判同刑）。
7. **词形归一 ≠ 同刑合并**：改 `妾犯妻`→`媵妾犯妻` 等词形，**只在"同一文件/同刑"里才允许**（`妾犯妻`+`媵犯妻` 同法条同刑同十恶 = 三者同，才并成 `媵妾犯妻`）；**同一文件只有其一**时必须保留原词形（否则会单主体文件里凭空引入另一主体，如 徒一年半 原仅 `妾犯妻`、流三千里 原仅 `媵犯妻`，都不能改成 `媵妾犯妻`）。判断合并前提是"法条+刑罚+十恶 三者同"，不是只同刑。
8. **`尊长`=上位聚合词（`尊属`+`兄姊`），**逐档合并**：`尊属`/`兄姊` **同刑且后果相同**才合并为 `X尊长`（如 `小功尊长（致死）`、`缌麻尊长（致折跌肢体二件…）`）；**后果仅有其一**的档保留原 `X尊属`/`X兄姊`（如 流三千里 `小功尊属（致折跌肢体、瞎一目）` 仅尊属有 → 保留）。`尊长` 不是 `尊属` 的别名，勿当要统一的词形。**常见误区**：某级"尊属/兄姊并存"≠该合并，须逐档判断**共同后果**才有交集（徒三年/徒二年半 等虽并存但无交集 → 不合并）。
9. **中文路径下 git show 用正斜杠**：Windows 下 `os.path.join()` 生成反斜杠路径，`git show HEAD:<path>` 会因反斜杠找不到路径返回空（leading 到误清空文件）。必须 `path.replace(os.sep,'/')` 转正斜杠再传 git；`git show` 是只读安全命令。
10. **改文件前先以 HEAD 校验基准 + 保留末尾换行**：写回脚本容易丢末尾换行（`\ No newline at end of file`）、误动非殴打行。应在 `git show HEAD:<file>` 基准基础上只替换目标块，其余字节（含末尾换行、非目标行）原样保留，改完用 `git diff --stat` 确认真实改动面。
11. **致死以五行表为准，勿信汇总表自身值**：`斗杀`/`故杀` 等汇总表可能本身含错（曾 `故杀` 夫殴媵妾=斩，实为徒三年）。核对/修改致死前，必须读对应 `斗殴/故殴量刑表（主体）` 的"致死"行为权威；禁止用汇总表现值反推、再扩散。
12. **多表文件的删除/回退同样必须按 `<x-table>` 分块**：全局字符串匹配（如删 `（故殴）致死 斩`）会跨表误删——曾误删同文件 `2-媵妾/-.xml` 中 妻对媵妾 表的正确行，直到用户追问才发现。合并/修改/**删除/回退**一律先 `git diff`/读文件看结构 + 按 `<x-table>` 分块，判同刑 key 含 法定刑。
13. **`5-尊卑相犯` 用聚合表述，勿按五行表逐档判缺**：该层用"用汤、火伤人"代表汤火致伤（取 `灼烂皮肤` 档刑），"未伤/斫射/拔发/致伤/致血"等轻档由代表行覆盖（豁免于"行名/分组一致"）。判断缺失须先理解此惯例，勿因五行表有独立 `灼烂皮肤` 档就补入 5-尊卑相犯（曾误加 4 行后被删）。
14. **核对 pattern 覆盖变体**：`（致死）` 精确匹配会漏 `（用刃致死）`。扫"致死"行用宽匹配 `用刃致死|故殴致死|斗殴致死|致死` 再人工复核，避免误判"缺失"。

## 可复用脚本（`scripts/`）

集中存放有复用价值的脚本（一次性/含 bug 的旧版本不入库，如 `dsh_write.ps1` 已废弃）：

- **`scripts/reorder_ou.py`** — 量刑表"殴打"块 重排+词形归一+同刑合并+去重，幂等。默认 dry-run（只打印不改），`--write` 才写回；其余字节（非殴打行/末尾换行）原样保留。内置 `merge_zunzhang` **逐档尊长合并**（同刑且后果相同才并 `X尊长`，独有档保留）。
  - 用法：`python scripts/reorder_ou.py [--write] [--only <文件子串>] [--remove-dup] [<目标目录>]`
  - 排序规则见脚本内 `sortkey()`（标记 斗殴→故殴→无标记；大类 凡人→夫妻→特定→通用；同主体多行按原序）。
  - 词形归一见 `RULES`，且**仅同类齐全（presence 判断）才并**——`妾犯妻`/`媵犯妻` 同文件同刑三者同才并 `媵妾犯妻`；single-only 保留原词形。
- **`scripts/reorder_zhuangzhi.py`** — 转置表（斗殴/故殴之一~之六 + 斗杀/故杀）客体行重排，幂等。默认 dry-run（只打印差异），`--write` 才写回；保留原换行风格（LF/CRLF）、表头行、非数据行；不改任何刑罚值。目标顺序见上文"排序规则"小节。
  - 用法：`python scripts/reorder_zhuangzhi.py [--write] [--only <文件子串>] [<目标目录>]`
  - 默认目录 `src/释义/量刑表/殴打`；仅对匹配 `^(斗殴|故殴)量刑表之[一二三四五六]\.xml$` 或 `斗杀/故杀量刑表.xml` 的表生效。
- **`scripts/verify_ou.py`** — 只读校验：mark 顺序 + 大类顺序，`--dir`/`--only` 可选。
  - 用法：`python scripts/verify_ou.py [--dir <目录>] [--only <文件子串>]`
- **`scripts/restore_head.py`** — 把误改的同量表文件还原为 HEAD 精确字节（只读 `git show`，不触碰 checkout/reset）。
  - 用法：`python scripts/restore_head.py [<路径/目录>] [--only <文件子串>]`

> ⚠️ Windows 中文路径：`os.path.join()` 生成反斜杠路径，`git show HEAD:<path>` 会**找不到路径返回空**（据此"恢复"会误清空文件）。必须先 `path.replace(os.sep,'/')` 转正斜杠再传 git。

## 注意

- `5-尊卑相犯` 的"殴打/斗殴"表采用"只列阶梯代表行"的简化风格：同刑罚的拔人头发方寸以上、（用手足）致伤、（用手足）致血从耳目出、（用器物）斫射未着身等情形不单列，由未伤/重伤代表行覆盖——此项豁免于"行名/分组一致"要求；`4-量刑表` 与转置总表（之一~之六）仍须完整收录。
- `4-量刑表`/`5-尊卑相犯` 的"用汤、火伤人"代表汤火灼伤（取五行表"灼烂皮肤"档的用汤火值），**不单列"灼烂皮肤"**；核对/判缺时勿因五行表有独立"灼烂皮肤"档就补入（曾误加 4 行后被删）。
- 禁止仅凭单一来源判断刑罚，须与量刑表五行表交叉核对后再修改，`5-尊卑相犯` 同受此约束。
- 修改后如运行 generator，交用户执行，不自行运行测试。
