# sync-sentencing：量刑全链路同步

本 skill 用于对《唐律疏议》项目的量刑内容做**全链路同步**：以 `src/释义/量刑表/` 为唯一基准，保持以下四处来源互相一致：

(1) `src/释义/量刑表/`（基准）
(2) `src/附录/3-罪刑表/`
(3) `src/附录/4-量刑表/`
(4) `src/附录/5-尊卑相犯/`

**铁律（先读）**：
1. **基准数据以 `src/释义/量刑表` 为准；基准文件不存在时，由用户提供**——停下向用户索要，不得仅凭律文自行推导定值。
2. **欲新建不存在的文件时，必须征得用户同意**——新增释义量刑表文件、5-尊卑相犯 主体文件、3-罪刑表 罪行文件均属新建；在现有文件内插入条目不算新建。**「全链路同步」「全链路补充」等指令不构成新建授权**：即使拟建文件内容已定稿，也须单独请示并等待明确同意（按全局「开工确认纪律」）。用户明确不建时，按用户给定律文只写现有行，并在提交说明注明基准缺位。
3. **只插入，不动已有**：不修改、移动、删除用户已写入的内容与顺序；新条目插进既有间隙，存疑时追加到节末。
4. **一处改动、其余同步**：改完用脚本逐格校验，勿仅目检。
5. **word value 必须与 `src/释义/` 下对应表文件名（不含扩展名）精确一致**（generator `CollectWords` 以文件名为 key）；改动完整名/代表名时，须同步重命名对应表文件并同步四处来源内全部 `<word value>` 引用，否则引用失效（正文内引用由用户自理，见铁律 6）。
6. **全链路同步不含 `src/正文/`，正文不得阅读**——四处来源之外的正文（law 文字、`<word>` 引用）一律由用户自理：**不得阅读**（Read/cat/grep 等任何方式均不得，**不得有任何借口**——"确认律文表述""核对法条号"等理由一律不成立）、不修改、不代改，也不把正文列入检查清单、方案或汇报的任务项；即使发现正文缺引用或表述与投影不一致，也不得据此动手，仅在用户明确指派时才碰。
7. **法条号由用户告知**——新增条目需要法条编号而用户未告知时，**停下向用户提问**；不得从正文读取获取（铁律 6），也不得自行推断或以其他来源的引用充当用户口径。
8. **涉及斗殴/故殴/殴打的罪刑，必须一并修改 6+1 表**——斗殴侧＝`斗殴量刑表之一~之六`＋`斗杀量刑表`，故殴侧＝`故殴量刑表之一~之六`＋`故杀量刑表`。凡新增/修改该罪名维度的任何内容，六张转置表与致死汇总表都须**逐表核对并同步**，不得以"同值不单列""伤档全无罪"等理由自行跳过。是否单列遵循既有先例：殴伤全无罪的主体行**显式列出**（弟妹/兄弟之子/子孙）；仅伤档与服级聚合行（小功卑幼/缌麻卑幼 等有刑行）全同值的主体才不单列（兄弟之孙/外孙）；拿不准时停下向用户提问。

## 四处来源的定位

| 来源 | 路径 | 定位 |
|------|------|------|
| 释义量刑表（**基准**） | `src/释义/量刑表/` | 五行（后果×手段）基准表，按罪名分子目录：`殴打/`（殴打量刑表系列）、`殴打/斗殴/`（斗殴量刑表系列 + 斗杀量刑表）、`殴打/故殴/`（故殴量刑表系列 + 故杀量刑表）、`过失杀伤/`（过失杀伤量刑表系列） |
| 罪刑表 | `src/附录/3-罪刑表/` | 按罪行分文件的罪刑对应总表（如 `8-斗讼律/1-斗殴.xml`、`2-故殴.xml`、`3-过失杀伤.xml`、`5-詈骂.xml`），含总结表与 `<word>` 引用 |
| 量刑表 | `src/附录/4-量刑表/` | 按刑罚等级（死刑/流刑/徒刑/杖刑/笞刑）分类的罪刑对应表 |
| 尊卑相犯表 | `src/附录/5-尊卑相犯/` | 按尊卑主体（父母子女、夫妻、期亲、大功、小功、缌麻、部曲奴婢主人）分类的罪刑对应表（x-table） |

**"之一~之六"的范围**：本 skill 所称"之一~之六"（转置总表）包含**两套十二个文件**——`殴打/斗殴/斗殴量刑表之一~之六` 与 `殴打/故殴/故殴量刑表之一~之六`；同属该体系的还有 `殴打/斗殴/斗杀量刑表`、`殴打/故殴/故杀量刑表`（致死类汇总表）。凡涉及"之一~之六"的核对，均须同时覆盖斗殴与故殴两套，且致死行须与斗杀表、故杀表交叉核对。**反向同样成立（铁律 8）**：凡涉及斗殴/故殴/殴打的罪刑改动，6+1 表必须一并修改核对，不得跳过。

**"殴打"的双重罪名属性**：`殴打/殴打量刑表` 系列（殴打类基准表，如殴打量刑表（妻殴夫）、（缌麻兄姊）、（缌麻尊属）、（小功兄姊））**同时被斗殴罪刑表（`1-斗殴.xml`）与故殴罪刑表（`2-故殴.xml`）引用**——即"殴打 = 斗殴 + 故殴"两个罪名维度共用同一基准表。因此：罪刑表的斗殴、故殴两处都须引用对应的殴打量刑表；`4-量刑表` 中殴打类条目仅以"殴打（主体）"呈现，**不单列"故殴（主体）"条目**（故殴维度由殴打表与故殴量刑表系列覆盖）。

## 为什么需要一致

释义量刑表是**权威详细表**（后果×手段的完整刑罚矩阵），其余三处是对它的投影/归类：
- `1-斗殴.xml`、`2-故殴.xml` 通过 `<word>` 引用转置总表（斗殴/故殴之一~之六）及斗杀、故杀表，行/列刑罚必须与量刑表一致
- `4-量刑表` 将量刑表各行的刑罚按等级归入对应刑罚文件，条目及其刑罚必须与量刑表一致
- `5-尊卑相犯` 将亲属尊卑相犯的刑罚按主体归入对应文件（父母子女、夫妻、期亲、大功、小功、缌麻、部曲奴婢主人），条目及其刑罚必须与量刑表一致

一处改动而不同步其他处，会导致网站各页刑罚互相矛盾。

## 同步流程（通用）

1. **读基准**：定位 `src/释义/量刑表/` 下对应主体的五行表并通读；**不存在时停下向用户索要基准数据**，用户提供前不得动手落值。
2. **列清单**：按下一节「全链路同步检查清单」逐项标注 改/不改及理由，其中涉及新建文件的，先征得用户同意。
3. **逐处同步**：按「修改/补充时的一致性检查」与下述各来源细则执行；情节间的合并关系**查 `config/情节合并配置.txt`**（硬编码），不得自行推断。
4. **逐格校验**：用 `scripts/verify_jiandeng.py`（减等派生）或覆盖率校验脚本对照基准表逐格验证；合并类改动再用 `scripts/scan_merge.py` 全库复扫。
5. **报告**：向用户列出各处插入/修改清单，以及扫描残留的待处理项。

## 来源细则：释义量刑表（基准）

- x-table 五行表：行=后果（`\n` 合并同类）、列=手段（用手足/用器物/用汤、火/用刃/用兵刃）；格式与对齐规范见 **x-table-converter** skill（整表对齐用 `align_xtable_full.py`，**× 按 1 格计宽**）。
- **派生惯例**：由某主体殴打表派生新主体表（如 过失杀伤=对应殴打表逐格减 N 等、卑幼相邻减一等）时：
  - 逐格减等（二死、三流各同为一减；徒三年减一等=徒二年半），用 `scripts/verify_jiandeng.py` 逐格校验；
  - 保持源表的 `\n` 合并行结构与行序；
  - 按罪名惯例增删行（如 过失杀伤删「未伤」「斫射」「拔人头发方寸以上」行——过失以伤、杀结果为前提）。

## 来源细则：3-罪刑表

- 按罪行分文件，文件内按主体/亲属区块 `<h2>` 分区；每区块可为简表（客体×法定刑×法条）+ `<word value>` 引用释义表展开详表（如 `3-过失杀伤.xml` 的 夫妻/父祖/期亲 区块）。
- **殴系双重属性**：`1-斗殴.xml` 与 `2-故殴.xml` 共用殴打系列基准表，两处都须引用对应释义表；新增/改名释义表时两处同步。
- 改释义文件名时，同步本目录（3-罪刑表）内全部 `<word value>`；正文内的引用由用户自理，不代改（铁律 6）。

## 来源细则：4-量刑表

- 按 20 级刑罚分文件（如 `3-徒刑/1-徒三年.xml`）+ `6-上请.xml`。
- 条目格式：`罪行\t情形\t十恶（无则 -）\t法条`；情形列=主体（后果），含手段前缀。
- 手段前缀：默认手段（手足/器物/汤火）不写前缀；刃/兵刃与默认手段不同档时写「用刃…」；「用汤、火伤人」（即灼烂皮肤档）需单独列举、行名仅写作「用汤、火伤人」，**不并入「致折伤」**，但与「致伤」同档同值时可并入「致伤」；轻后果的「用汤、火」列并入「用器物」列（详见 `config/情节合并配置.txt`）。
- 插入锚点：同一罪行组内按法条序（如 326.1 → 328.2 → 329.2），组内按主体排序规则；**只插入不动已有**。
- **多后果折叠**：同刑罚级内哪些后果可并入哪个代表行，查 `config/情节合并配置.txt`（前提：量刑一致、代表行存在、手段前缀不变）；合并后的行用代表行名（如折齿~堕胎并入「致折伤」）。
- 殴系的合并/格式规则见下文「4-量刑表 斗殴/故殴/殴打 合并格式」「同一主体多行合并」。

## 来源细则：5-尊卑相犯

- 按尊卑主体分目录/文件；一个文件可能含多张 `<x-table>`（不同关系），**必须按表分块处理**。
- 行粒度**跟随该文件自身殴打块的粗细**（粗粒度代表行或细粒度逐后果），同值才可折叠，折叠关系查 `config/情节合并配置.txt`；同一主体在 4-量刑表 与本层的行骨架须同构；「（用刃）」作为手段须独立套括号。
- 殴系合并规则见下文「5-尊卑相犯 斗殴/故殴/殴打 合并」。

## 过失杀伤链路（实例：328.2 期亲尊长减二等）

以「过失杀伤量刑表（兄姊）」为例的完整链路，供同类任务参照：
1. **基准**：`殴打/殴打量刑表（兄姊）` 逐格减二等（律 328.2「各减殴杀伤二等」）→ `过失杀伤/过失杀伤量刑表（兄姊）`（删未伤/斫射/拔人头发方寸以上、保持 `\n` 合并、整表对齐）；
2. **正文（范围外，铁律 6）**：`328.2` 的 law 文字与 `<word value="过失杀伤量刑表（兄姊）"/>` 引用由用户自理，**不属同步任务步骤**（此处仅存档该链路的历史全貌）；
3. **罪刑表**：`3-过失杀伤.xml` 期亲区块放 `<word>` 引用；
4. **4-量刑表**：按代表行骨架拆条（徒二年 致伤 1 条 / 徒二年半 用汤、火伤人+致折伤 2 条 / 徒三年 用刃致伤+致折跌肢体、瞎一目+致死 3 条，共 6 条），插在 326.1 块后、329.2 祖父母父母之前；
5. **5-尊卑相犯**：该主体文件殴打块后加 过失杀伤 块（单一罪行组，致死即杀，6 行代表行，与 4-量刑表 同构）。

## 主体命名规范（完整名 vs 代表名）

用户既定命名规则，适用于亲属主体称谓：

- **仅 `5-尊卑相犯` 层使用完整类推名**（完整列举）：如 `祖父母、曾祖父母、高祖父母`、`孙（女）、曾孙（女）、玄孙（女）`、`从父兄弟之子女`。
- **其余所有位置**（罪刑表 `1-斗殴.xml`/`2-故殴.xml`、正文、`4-量刑表`、转置表之一~之六、五行表专属表名）**使用代表名**：`祖父母`、`孙`、`从父兄弟之子`。

| 完整类推名（仅 5-尊卑相犯） | 代表名（其余） |
|---|---|
| 祖父母、曾祖父母、高祖父母 | 祖父母 |
| 孙（女）、曾孙（女）、玄孙（女） | 孙 |
| 从父兄弟之子女 | 从父兄弟之子 |

- **word value 必须与 `src/释义/` 下对应表文件名（不含扩展名）精确一致**（generator `CollectWords` 以文件名为 key）。改动完整名/代表名时，须**同步重命名**对应表文件，并同步罪刑表的 `<word value>`（正文引用由用户自理，铁律 6）；否则引用失效。
- `5-尊卑相犯` 的目录/文件名/表标题用完整类推名（如 `1-从父兄弟之子女.xml`），不受"其余用代表名"约束。
- **⚠️ 跨层派生须按目标层归一命名**：从某层向另一层复制/派生主体表（如从 `5-尊卑相犯` 新表复制出 `五行表`/`转置表`/`罪刑表`/`4-量刑表`）时，主体名必须按**目标层**规则重新归一，**禁止照搬源层词形**。
  - 反例（曾犯）：从 `5-尊卑相犯\...\2-从父兄弟之孙（女）.xml`（完整类推名层）派生五行表，照搬得 `斗殴量刑表（从父兄弟之孙（女））`——**错误**；应归一为 `斗殴量刑表（从父兄弟之孙）`。
  - 判定法：先问"目标所在层"——目标是 `5-尊卑相犯` 层 → 用完整类推名（含 `（女）`）；目标是其余层（罪刑表/正文/`4-量刑表`/转置表/五行表）→ 一律用代表名（去 `（女）`）。

## 排序规则（适用所有"殴打"情况）

适用于所有殴打情况（斗殴/故殴/殴打；不同来源/表可能缺少某些项，但大体排序都应遵守，缺项不补齐）：

1. **罪名标记**：斗殴 > 故殴 > 殴打（无标记）。
2. **客体先后**：以 `config/客体优先级.txt` 的 `--` 之上定序区为**唯一权威**（2026-10-25 用户手工排定 32 行；文件内空行为视觉分组、解析时跳过）：
   - 客体与定序区**完美匹配**（同名行）→ 取该行序；
   - **无完美匹配 → 前缀匹配**：取以其为前缀的最长定序行随其排序（如 `媵妾`→随 `媵`、`祖父母、父母`→随 `祖父母`、`夫之祖父母、父母`→随 `夫之祖父母`、`从父兄弟之子孙`→随 `从父兄弟之子`）；
   - 两者皆无 → **未确定客体**：补入该文件 `--` 之下待用户定夺，排序时暂置同组末尾。
3. **同客体级并列**：多行解析到同一定序行时（如 夫犯媵妾/妻犯媵妾/妾犯媵 皆随 `媵`），保持库内既有相对次序（现库表现为 主体 夫 > 妻 > 媵 > 妾）。

## 同一主体多行合并（同一主体+同法条+同刑罚级）

同一主体（同 标记+主体+法条+十恶）在某刑罚级文件里有**多行不同后果**时，合并为**一行**：
- **格内分行（2026-10-25 用户定）**：各行的情形（完整词形 `主体（后果）`）**按原行序**用字面 `\n` 连接写入同一格，如 `小功兄姊（用刃致伤）\n小功兄姊（致折肋、眇两目、堕胎）`——**不分两行，也不按最低后果省写**。合并行占组内首行位置（保留首行既有空格结构），删除组内其余行；十恶、法条列不变（组内须一致，不一致时停下询问）。2026-10-25 已按此口径全库合并 4-量刑表 殴打部分 88 组（含 （斗殴）/（故殴）标记行；标记逐行保留）。
- **未伤对称规则（2026-10-25 用户定，判定范围=同表内）**：**同一刑罚级文件内**该主体有多行（未伤行与致伤/其他后果行并存）时，未伤行必须显式写 **（未伤）**——目的是不让情形列（第二列）留空、与致伤行对称；**同表内该主体仅一行（只有未伤、无并存后果行）则省略（未伤）**，裸写主体。跨文件存在对称行不触发（曾在"跨库对称"口径下误补 12 行后撤销）。**同样适用于罪刑表简表与 5-尊卑相犯 的情形列**：同表内未伤行与致伤行并存时，未伤行情形列不得写通配 `*`（`*` 含致伤、与并存行重叠），必须写「未伤」（如 330.1 `夫之祖父母、父母 未伤 绞` + `夫之祖父母、父母 致伤 皆斩`）；单行时 `*` 才表全情形通配（如 329 `父母 * 斩`）。

## 实操技术教训（防止再犯）

1. **PowerShell 单元素数组展平**：`@(@('a','b'))` 会**展平**为 `@('a','b')`，导致循环取值变成逐字符；多元素 `@(@('a','x'),@('b','y'))` 不展平。单元素需用 `,@('a','b')` 或直接构造字符串，勿用单元素内层数组。
2. **减等映射须覆盖全部值**：如 徒一年半→徒一年，漏了会导致该档未减。
3. **字面反引号-t**：单引号 `'殴打`t...'` 是字面反引号+t，不会变成 Tab；构造含 Tab 的行要用双引号 `` "殴打`t..." ``。
4. **单行匹配别当数组**：`(... | Where-Object {...})` 单结果会成标量，`$r[0]` 取到首字符；需强制数组 `@(...)[0]`。
5. **逐格脚本校验**：改完用脚本对照基准表逐格验证（如 大功卑幼=小功卑幼-1），勿仅目检；"减 N 等派生"类改动直接用 `scripts/verify_jiandeng.py`。
6. **多表合并勿跨表**：一个 XML 文件含多张 `<x-table>`（不同关系）时，合并/改写须**按表分块**逐块处理；误用"全文件首次~最后出现"的 span 会把多张表并成一块丢主体区分（如 媵妾/-.xml 的 夫对媵妾 + 妻对媵妾）。合并前先 `git diff`/读文件确认结构。分组 key 务必含**法定刑**（避免不同刑被误判同刑）。
7. **词形归一 ≠ 同刑合并**：改 `妾犯妻`→`媵妾犯妻` 等词形，**只在"同一文件/同刑"里才允许**（`妾犯妻`+`媵犯妻` 同法条同刑同十恶 = 三者同，才并成 `媵妾犯妻`）；**同一文件只有其一**时必须保留原词形（否则会单主体文件里凭空引入另一主体，如 徒一年半 原仅 `妾犯妻`、流三千里 原仅 `媵犯妻`，都不能改成 `媵妾犯妻`）。判断合并前提是"法条+刑罚+十恶 三者同"，不是只同刑。
8. **`尊长`=上位聚合词（`尊属`+`兄姊`），**逐档合并**：`尊属`/`兄姊` **同刑且后果相同**才合并为 `X尊长`（如 `小功尊长（致死）`、`缌麻尊长（致折跌肢体、瞎一目）`）；**后果仅有其一**的档保留原 `X尊属`/`X兄姊`（如 流三千里 `小功尊属（致折跌肢体、瞎一目）` 仅尊属有 → 保留）。`尊长` 不是 `尊属` 的别名，勿当要统一的词形。**常见误区**：某级"尊属/兄姊并存"≠该合并，须逐档判断**共同后果**才有交集（徒三年/徒二年半 等虽并存但无交集 → 不合并）。
9. **中文路径下 git show 用正斜杠**：Windows 下 `os.path.join()` 生成反斜杠路径，`git show HEAD:<path>` 会因反斜杠找不到路径返回空（leading 到误清空文件）。必须 `path.replace(os.sep,'/')` 转正斜杠再传 git；`git show` 是只读安全命令。
10. **改文件前先以 HEAD 校验基准 + 保留末尾换行**：写回脚本容易丢末尾换行（`\ No newline at end of file`）、误动非殴打行。应在 `git show HEAD:<file>` 基准基础上只替换目标块，其余字节（含末尾换行、非目标行）原样保留，改完用 `git diff --stat` 确认真实改动面。
11. **致死以五行表为准，勿信汇总表自身值**：`斗杀`/`故杀` 等汇总表可能本身含错（曾 `故杀` 夫殴媵妾=斩，实为徒三年）。核对/修改致死前，必须读对应 `斗殴/故殴量刑表（主体）` 的"致死"行为权威；禁止用汇总表现值反推、再扩散。
12. **多表文件的删除/回退同样必须按 `<x-table>` 分块**：全局字符串匹配（如删 `（故殴）致死 斩`）会跨表误删——曾误删同文件 `2-媵妾/-.xml` 中 妻对媵妾 表的正确行，直到用户追问才发现。合并/修改/**删除/回退**一律先 `git diff`/读文件看结构 + 按 `<x-table>` 分块，判同刑 key 含 法定刑。
13. **`5-尊卑相犯` 用聚合表述，勿按五行表逐档判缺**：该层用"用汤、火伤人"代表汤火致伤（取 `灼烂皮肤` 档刑），"未伤/斫射/拔发/致伤/致血"等轻档由代表行覆盖（豁免于"行名/分组一致"）。判断缺失须先理解此惯例，勿因五行表有独立 `灼烂皮肤` 档就补入 5-尊卑相犯（曾误加 4 行后被删）。
14. **核对 pattern 覆盖变体**：`（致死）` 精确匹配会漏 `（用刃致死）`。扫"致死"行用宽匹配 `用刃致死|故殴致死|斗殴致死|致死` 再人工复核，避免误判"缺失"。
15. **插入/排位前先按身份定落点，来源≠落点**：往某层插入新主体条目时，先判断该主体身份归类（特定亲属 vs 通用亲属、尊/卑）与排序规则，确定落点**再选锚点**；**不要用"数据来源行"当锚点**（如从 `缌麻卑幼` 复制取值，不等于结果要排缌麻卑幼旁）。
   - 反例（曾犯）：为「从父兄弟之孙」（特定亲属/从父族系）取值自缌麻卑幼，却把条目插在缌麻卑幼后，违反"特定亲属>通用亲属"；而转置表用「从父兄弟之子」作锚点排对了 → 两处不一致。
   - 正确：特定亲属（从父兄弟族系）应排在通用亲属（大功/小功/缌麻卑幼）之前，并与从父兄弟之子/从父弟妹相邻。
   - **插后校验前后行**：检查该行"前一行/后一行"主体是否符合排序（前=特定亲属或更早大类，后=通用亲属），不符即回退重排。
   - **跨来源对齐**：同一主体在不同来源（转置表 / 4-量刑表 / 罪刑表）的相对排位须一致，插入时参照它其他来源已定的行序，勿各来源各找锚点。
16. **禁止以单次 grep 断言"不存在"**：`grep -l` 只能用于定位候选，**不能作为某表"没有对应行"的证据**。曾据 `grep -l 从父弟妹` 的输出误判故杀量刑表无卑幼行，漏改且把错误断言写进提交说明。对同体系多表做结构性增行/核对，必须**枚举文件逐个打开确认**；提交说明只写已核对的事实。
17. **克隆锚点行构造新行必须显式改首列行名**：曾沿用兄姊行的字段构造弟妹行却漏改首列，13 张转置表出现重复「兄姊」。插入后立即校验行名唯一性（如每表 `^弟妹\t` 恰 1 行、`^兄姊\t` 恰 1 行）。
18. **列数/列义校验**：x-table 解析忽略空 token、值顺次入列，多写/少写一格会使后续值整体错位（曾在 `2-故殴.xml` 简表多写「致死」一格，致流二千里落入十恶列）。插入后断言**每行有效值数 == 该表表头有效列数**；注意 `4-量刑表`（罪行/情形/十恶/法条）与罪刑表简表（客体/法定刑/十恶/法条）列义不同，不可照搬。
19. **插入落位：同法条家族聚簇、亲属尊→卑相邻**：`4-量刑表` 内同一罪行按法条家族聚簇，同一家族内亲属主体按尊→卑排列（期亲：兄姊 → 弟妹）。曾把弟妹行插到外祖父母之后被用户纠正；该刑罚级无兄姊行时（如流二千里），靠同法条家族的最近行落位（如 328 家族末尾、小功/缌麻之前）。
20. **"同值不单列"勿套到全无罪行**：殴伤全无罪的卑幼行（弟妹/兄弟之子/子孙）在转置表中是逐表**显式列出**的；该惯例只适用于伤档与服级聚合行（小功卑幼/缌麻卑幼 等有刑行）同值的主体（兄弟之孙/外孙）。曾据此把子孙行漏在斗殴转置六表之外，被用户以"斗殴6+1表遗漏"指正。凡涉及斗殴/故殴/殴打罪刑，6+1 表一律逐表核对并同步（铁律 8）。

## 可复用脚本（`scripts/`）与配置文件（`config/`）

集中存放有复用价值的脚本（一次性/含 bug 的旧版本不入库，如 `dsh_write.ps1` 已废弃）：

- **`config/情节合并配置.txt`** — 情节合并关系硬编码（`A => B`，前提量刑一致、代表行存在、手段前缀不变），是模型与脚本判断"哪些情节可并入哪些代表行"的唯一依据；含同级折叠（用汤、火伤人/致折伤 ⇒ 致伤）、行名映射（灼烂皮肤 ⇒ 用汤、火伤人，单独列举、不并入致折伤）、手段列合并（轻后果的用汤、火 ⇒ 用器物）、手段包含关系（用器物包含用刃，用刃包含用兵刃）与代表行骨架说明。

- **`config/亲属级别配置.txt`** — 亲属主体服级归属硬编码（`主体 -> 服级`，如 `夫之祖父母 -> 大功`）。判定 5-尊卑相犯 目录落位、区块归属与主体排序时**必须查此配置**；仅根据用户说明补充，未收录的主体不得自行依服制推断，须询问用户。**多主体行部分未登记时必须先问**：一行含多个主体（如「夫之祖父母、父母」）而其中部分主体服级未登记时，该行的落位/拆分必须先向用户提问，**不得默认整行随已登记主体落位**——落位没有"中性默认值"，落下去就是替用户决定（2026-10-25 曾整行随夫之祖父母落大功被指正，后经询问拆为 夫之祖父母@大功＋夫之父母@期亲）。**亲等拆分边界（2026-10-25 用户规则）**：**没有区分亲等章节的部分不任意拆开**——6+1 转置表整体无亲等分区，多主体合并行（如「夫之祖父母、父母」）**合并写、不拆**；**区分亲等的章节必须严格按照亲等落入章节**——罪刑表简表的期亲/大功/小功/缌麻区块必须把多主体行按各主体服级拆开分落（夫之父母→期亲区块、夫之祖父母→大功区块）。`4-量刑表`（按刑罚级组织）与 5-詈骂类单表无亲等分区，保持合并词形，不得自行扩散拆分。

- **`scripts/reorder_ou.py`** — 量刑表"殴打"块 重排+词形归一+同刑合并+去重，幂等。默认 dry-run（只打印不改），`--write` 才写回；其余字节（非殴打行/末尾换行）原样保留。内置 `merge_zunzhang` **逐档尊长合并**（同刑且后果相同才并 `X尊长`，独有档保留）。
  - 用法：`python scripts/reorder_ou.py [--write] [--only <文件子串>] [--remove-dup] [<目标目录>]`
  - 排序规则见脚本内 `sortkey()`（标记 斗殴→故殴→无标记；大类 凡人→夫妻→特定→通用；同主体多行按原序）。
  - 词形归一见 `RULES`，且**仅同类齐全（presence 判断）才并**——`妾犯妻`/`媵犯妻` 同文件同刑三者同才并 `媵妾犯妻`；single-only 保留原词形。
- **`scripts/reorder_zhuangzhi.py`** — 转置表（斗殴/故殴之一~之六 + 斗杀/故杀）客体行重排，幂等。默认 dry-run（只打印差异），`--write` 才写回；保留原换行风格（LF/CRLF）、表头行、非数据行；不改任何刑罚值。目标顺序见上文"排序规则"小节。
  - 用法：`python scripts/reorder_zhuangzhi.py [--write] [--only <文件子串>] [<目标目录>]`
  - 默认目录 `src/释义/量刑表/殴打`；仅对匹配 `^(斗殴|故殴)量刑表之[一二三四五六]\.xml$` 或 `斗杀/故杀量刑表.xml` 的表生效。
- **`scripts/verify_ou.py`** — 只读校验：mark 顺序 + 大类顺序，`--dir`/`--only` 可选。
  - 用法：`python scripts/verify_ou.py [--dir <目录>] [--only <文件子串>]`
- **`scripts/verify_jiandeng.py`** — 只读校验：派生量刑表 = 源量刑表**逐格减 N 等**（默认 N=2）。适用于"从某主体殴打表复制派生、全表减 N 等"的场景（如 328.2 过失杀伤期亲尊长「各减殴杀伤二等」→ 过失杀伤量刑表（兄姊））。校验：行名（含 `\n` 合并）与行序须与源表一致、仅允许缺 `--drop` 列出的行；`\n` 合并行组内源值须相同（合并非法时报错）；数值按五刑二十等阶梯减等（**二死/三流同为一减**、徒三年减一等=徒二年半）；源值尾注（如 斩（以故杀论））自动剥离后比对；`×` 与 `×` 对应。全过输出 OK（行/格统计），否则逐条 FAIL 退出码 1。
  - 用法：`python scripts/verify_jiandeng.py <源表.xml> <目标表.xml> [--n 2] [--drop 未伤,斫射,拔人头发方寸以上]`
- **`scripts/scan_merge.py`** — 只读扫描：按 `config/情节合并配置.txt` 的 `[合并]` 规则，找出 `4-量刑表` / `5-尊卑相犯` 中**尚可合并的行**（同罪行/主体/法条、同刑罚级、同罪名标记、B 行存在且手段集覆盖 A）。输出即可合并清单；无输出为"未发现可合并内容"。合并口径变更后必须全库重扫；**不得用它自动改写**，逐项交用户决定。
  - 用法：`python scripts/scan_merge.py [--root <仓库根>]`
- **`scripts/restore_head.py`** — 把误改的同量表文件还原为 HEAD 精确字节（只读 `git show`，不触碰 checkout/reset）。
  - 用法：`python scripts/restore_head.py [<路径/目录>] [--only <文件子串>]`

> ⚠️ Windows 中文路径：`os.path.join()` 生成反斜杠路径，`git show HEAD:<path>` 会**找不到路径返回空**（据此"恢复"会误清空文件）。必须先 `path.replace(os.sep,'/')` 转正斜杠再传 git。

## 注意

- `5-尊卑相犯` 的"殴打/斗殴"表采用"只列阶梯代表行"的简化风格：同刑罚的拔人头发方寸以上、（用手足）致伤、（用手足）致血从耳目出、（用器物）斫射未着身等情形不单列，由未伤/重伤代表行覆盖——此项豁免于"行名/分组一致"要求；`4-量刑表` 与转置总表（之一~之六）仍须完整收录。
- `4-量刑表`/`5-尊卑相犯` 的「用汤、火伤人」行（即五行表"灼烂皮肤"档）**需单独列举、不并入致折伤**（与致伤同档同值时可并入致伤）；核对/判缺时勿因五行表有独立"灼烂皮肤"档就补入（曾误加 4 行后被删）。
- 禁止仅凭单一来源判断刑罚，须与量刑表五行表交叉核对后再修改，`5-尊卑相犯` 同受此约束。
- 基准数据缺失（`src/释义/量刑表` 无对应文件）时，停下由用户提供，不得自行定值。
- 欲新建不存在的文件（释义量刑表新表、5-尊卑相犯 新主体文件、3-罪刑表 新罪行文件等）必须先征得用户同意。
- 修改后如运行 generator，交用户执行，不自行运行测试。
