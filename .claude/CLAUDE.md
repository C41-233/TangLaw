# 项目

本项目是《唐律疏议》的注解网站，通过generator工具将src的内容转化输出到docs，网站入口在docs/index.html。

## 目录结构

- references 参考文献，不应当读取
- src 原始文档
- docs 输出的静态网站页面
- generator 一个dotnet项目，用于将src的原始文本内容转化输出到docs

### src的目录结构

src包含序言、正文、附录、释义。

序言只有 `0.xml`，是序言的全部内容。

正文分为三层，第一级目录是`篇`，第二级目录是`章`，第三级的文档具体的`条。`

目录和文档的命名格式都为 `<number>.<xxx>` 数字表示其序号，xxx表示其标题。`0.xml`是特殊的文档，表示该级目录本身的内容。

### 文档结构

文档是自定义的格式，非完全XML格式。

#### src

`<src>` 内是古文原文。

#### law

`<law>` 内是条文。

#### 正文

其余所有内容都是正文，格式规则包括：

- `>` 标记了一级标题，`>>` 标记二级标题，以此类推。

### docs的目录结构

styles是样式目录，contents是generator的输出目录，里面包含所有的输出html文档。

generator负责在contents中生成index.html以及其他详情页面。

index.html是网站入口，从上到下依次包含：

- 标题 `《唐律疏议》的理解与适用`
- `正文`的目录（序言包含其中），按照篇、章、条的层级，点击可以跳转到详情页面。
- 律文，合并显示所有正文的律条（law），也包括序言。

详情页面的内容，从上到下依次是：

- 标题，即本条的标题。
- 条文，对应`<law>`中的内容。
- 正文，xml文档的主要部分内容，即law和src以外的所有内容。
- 原文，对应`<src>`中的内容。

详情页面的标题，根据其所处的层级和序号，要显示为 `第一篇 名例律` `第一章 刑罚` `第一条 笞刑`，注意中文数字，对目录同样如此。序言只显示为`序言`。

### 加等规则（完整逐等对照）

|------|---------|
| 笞一十 | 笞二十 |

| 笞四十 | 笞五十 |
| 笞五十 | 杖六十 |
| 杖六十 | 杖七十 |
| 杖七十 | 杖八十 |
| 杖八十 | 杖九十 |
| 杖九十 | 杖一百 |
| 杖一百 | 徒一年 |
| 徒一年 | 徒一年半 |
| 徒一年半 | 徒二年 |
| 徒二年 | 徒二年半 |

| 徒三年 | 流二千里 |
| 流二千里 | 流二千五百里 |
| 流二千五百里 | 流三千里 |
| **流三千里** | **→ 必须询问用户是否加至死刑** |
| **绞** | **→ 必须询问用户是否加至斩** |

**"流三千里加一等"特例**（不得自行断定）：
- **身份加等**（如"各加一等"、"与犯夫同"、"尊属者又各加一等"、"小功大功各递加一等"）**可加至死刑**（流三千里加一等 = 绞）。
- **递加凡斗伤**（如"加凡人一等"、"各递加凡斗伤一等"）**罪止流三千里**、不加至死刑（依据唐律"罪止远流"，如《斗讼律》327 条疏议"不云加入于死，罪止远流"）。
- 凡出现"流三千里加一等"，先询问用户该处是否加至死刑，再落值。

**"绞加一等"特例**（不得自行断定）：绞加一等（→斩）涉及是否加至斩，同样**须询问用户**该处是否加至斩，不得自行断定。

**致死档**：通常由律文直接规定（"死者斩/绞"），加等不得自行推导至致死档；致死行以律文为准。

### 减加等操作注意事项（防错清单）

1. 徒三年减一等=徒二年半（不是徒二年）；减二=徒二年
2. 刃/兵刃档与手足/器物/汤火档**不同值**，须逐档单独计算（勿用相近档替代）
3. 减等/加等完成后，用脚本逐格验证（对照凡人基准表推导），不得仅靠目检
4. 流刑/死刑的减等先按"二死/三流同为一减"跳档，再逐级

## 基础规则

- 允许执行无副作用的只读 `git` 命令（如 `git log`、`git diff`、`git status`、`git show` 等），用于查看提交历史与工作区变更；禁止执行任何有副作用的 `git` 命令（如 `checkout`、`reset`、`commit`、`push`、`merge`、`stash` 等）。
- 不允许删除任何文件。
- 代码修改完毕后，只允许测试编译通过。禁止自行运行测试，必须交由用户代为执行。
- 未经允许，不得修改正文（`src/正文/` 目录下的内容）。
- `src` 下的所有文件必须以 CRLF（`\r\n`）格式保存。
